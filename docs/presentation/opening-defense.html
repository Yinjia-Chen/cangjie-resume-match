研究背景与课题目标

把分散的简历信息转化为可比较、有依据的筛选结果

业务起点

简历以 PDF、Word 和图片等形式出现，岗位描
述又使用不同表达，比较前需要整理信息。

核心需求

围绕岗位要求，查看候选人具备哪些能力、依据
在哪里，以及哪些内容还需要核实。

系统目标

连接简历解析、岗位建模、匹配推荐和面试辅助，
减少流程中的重复整理。

应用定位

为 HR 提供可追溯的筛选参考，保留原文与人工
判断，不把总分直接等同于录用决定。

相关研究与本课题的技术取舍

参考人岗匹配与文档解析研究，聚焦可追溯的应用实现

人岗表示

PJFNN 研究简历与岗位的联合表示，关注具体能
力要求的匹配。

能力关联

APJFNN 将岗位要求与求职经历关联，关注不同
经历对能力判断的贡献。

文档解析

Docling 提供本地文档转换、版面分析与表格识
别，为结构化处理提供依据。

课题取舍

复用解析工具与模型 API，由仓颉组织证据、校
验与评分，不训练基础模型。

研究用于说明方法来源，相关论文的实验成绩不作为本系统结果。

总体架构：前端与本地引擎

A 架构规划：Sites 负责交互，Mac 是唯一业务计算位置

Sites 前端Worker 转发Mac 仓颉引擎

请求进入引擎 / JSON 返回站点

站点侧

Sites 提供上传、JD 录入和结果页面，Worker 负
责请求转发与状态查询。

引擎侧

Mac 运行仓颉和 Docling，完成文档处理、岗位
模型、匹配计算与结果组织。

数据交换

站点发请求，引擎返回 JSON；浏览器展示引擎
结果，不重算分数或排名。

架构与现场请求链路属于拟实施方案，当前并非已上线服务。

05 / 16

一次筛选任务怎样完成

让岗位确认、现场计算与结果查看形成连续流程

上传与提交

HR 上传候选简历并填写 JD，站点提交本次评估
文件集合，获得任务标识。

岗位确认

引擎将 JD 转为结构化岗位要求，HR 确认或修正
后，冻结本次评估配置。

计算与查询

引擎处理解析、匹配和理由，站点查询任务状态，
避免长时间停留在一次请求中。

结果查看

HR 浏览候选列表并进入详情，核对能力依据；
修改岗位要求后建立新的评估版本。

06 / 16

简历解析与证据表示

不仅取得文本，还要保留能力判断能够回到的来源

文件处理

仓颉按文件格式调用本地解析工具；旧 Word 文
件先转换，再进入统一解析流程。

文本位置

保存文本片段和来源引用，保留可获得的段落、
页码与位置，支持详情页回看。

能力结构

拟抽取技能、经历起止、项目职责成果、学历与
行为事例，并保留对应证据标识。

字段处理

同义词作统一表示，缺失字段保留未知；软素质
需要具体行为，不能只凭自我评价。

本地解析链路已验证；面向模型的业务字段抽取目前仍是接口骨架。

07 / 16

岗位模型怎样组织要求

仓颉结构体与 JSON 表示，确认后固定评估依据

技能经验学历软素质

要求项

每项记录所属维度、目标水平、是否必需与项权
重，让岗位描述能够逐项对照。

人工确认

JD 转模型后交由 HR 检查，避免直接把原始文字
当作已经确定的筛选条件。

版本快照

确认后冻结完整岗位配置；修改要求或权重需新
建版本，不把不同配置的结果混排。

08 / 16

多维匹配与确定性计算

语义判断提供逐项依据，仓颉负责可复现的分数汇总

逐项对照

围绕技能、经验、学历与软素质，将每项岗位要
求与相关能力证据关联。

加权汇总

先在各维度内按项权重汇总，再按维度权重计算
总分，规则由仓颉统一执行。

未知处理

信息缺失或判断依据不足时保持待核实，不当作
已满足，也不据此认定缺乏能力。

结果组织

同时输出总分、分项结果、证据覆盖情况与推荐
理由；前端只展示引擎返回的数据。

09 / 16

推荐理由怎样落到原文

合成示例：说明证据与结论的关系，不是模型实测结果

岗位要求

能够使用 JavaScript 完成前端开发。

简历原文

“使用 JavaScript 实现表单校验，并参与接口联
调。”

可支持判断

存在技能使用与开发经历的证据；仅凭这句话，
仍需核实熟练程度和独立承担范围。

页面呈现

将要求、原文引用与待核实项放在一起，HR 可
回到来源，而非只看到一个总分。

仓颉程序与模型接口的分工

模型接入放在引擎层，计算与校验仍由程序控制

仓颉程序

管理输入与岗位快照

校验字段、引用及分值

计算分数并组织结果 JSON

模型接口（待接入）

抽取简历能力与岗位要求

判断经历与要求的语义关系

依据证据生成面试问题

输出处理

模型结果先经过字段和证据检查，再进入计算；
接口未接入时保持未知，不补造结论。

页面设计与操作入口

围绕筛选任务组织页面，展示与计算职责分离

上传与岗位

选择简历、填写 JD，查看处理状态，并确认引擎
生成的岗位要求。

候选人列表

展示候选结果与能力概览，提供定位候选人的入
口，保持引擎给出的原始顺序。

详情与理由

按岗位要求查看原文依据、优势、缺口与待核实
项，方便 HR 逐项核对。

面试区域

预留问题、考察点与追问展示；问题生成由引擎
实现，页面不直接调用大模型。

以上为页面规划，当前尚未完成 Sites 与 Mac 的现场请求链路。

实验设计与评价方法

拟开展：对比系统输出、关键词基线与人工参考

样例准备

覆盖多个岗位与脱敏简历，包含不同文件形式及
匹配、边界和信息不足的样例。

人工参考

由标注者独立判断相关性，讨论分歧；按候选人
划分开发集与测试集，避免混用。

对比方式

使用相同样本比较关键词规则与本系统，在测试
前固定模型、提示词和评估配置。

评价内容

用 F1、Recall 与 NDCG 评价筛选和排序，另核
对字段、理由与面试题，并记录耗时成本。

本页是实验方案，数据收集与效果实验尚未完成。
